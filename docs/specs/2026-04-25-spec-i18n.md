# i18n — Full UI + Output Language Coupling

**Date:** 2026-04-25
**Status:** Spec — eng review CLEAR · ready for plan phase
**Scope:** Chrome extension `reader/` + `options/` UI strings; AI prompt language coupling
**Eng review:** 2026-04-25 — D6/D14 自定义 picker 删除；新增 D16-D19；D10 深链路修正；Options 页删本地 state；4 critical gaps 闭环

## Summary

Expand UI language support from 2 locales (`zh-CN`, `en-US`) to **9 locales**
matching the existing `OUTPUT_LANGUAGES` list — `en`, `zh-CN`, `zh-TW`,
`ja`, `ko`, `fr`, `de`, `es`, `ru`. Auto-detect the initial locale from
`navigator.language`. Make `t()` reactive so a locale change propagates to
all open extension surfaces without a reload. Tighten the Output language
"Auto" semantics so it lazily resolves to the current UI locale at AI
request time, replacing today's model-heuristic behavior. Translate every
user-visible string in `reader/` and `options/` (existing ~80 keys +
~67 new keys = ~150 keys × 9 locales ≈ 1,200 lines of translated text).

## Motivation

Two gaps drive this work:

1. **Output language `'auto'` is decoupled from UI language.** Today
   `OUTPUT_LANGUAGES.find(l => l.code === 'auto').instruction` is
   *"Respond in the reader's language if they asked in one; otherwise
   default to English."* — model heuristic. A user with Japanese UI who
   asks in English gets English replies, even though they explicitly
   chose Japanese as their interface. The user's mental model is
   "default = my UI, override if I want to."

2. **UI language is binary.** Even though the AI side already supports
   9 output languages, the UI itself has only `zh-CN` and `en-US`. A
   French or Japanese reader sees an English UI as fallback — adequate
   but not what `navigator.language` alignment would suggest.

These are the two requirements stated by the user:

> 1. 输出的多语言默认同步界面多语言，也支持自己设置输出多语言
> 2. 多语言默认和浏览器语言对齐

## Data Model

### Locale type

```ts
// reader/lib/i18n.ts
type Locale = 'en' | 'zh-CN' | 'zh-TW' | 'ja' | 'ko' | 'fr' | 'de' | 'es' | 'ru'
```

### Storage schema

```ts
// reader/lib/storage-schema.ts
config_uiLanguage: Locale  // was: 'zh-CN' | 'en-US'
```

`config_outputLanguage` shape unchanged — still a string from the
`OUTPUT_LANGUAGES` set including `'auto'`.

### One-time migration

On module load:

```ts
const stored = await chrome.storage.local.get('config_uiLanguage')
if (stored.config_uiLanguage === 'en-US') {
  await chrome.storage.local.set({ config_uiLanguage: 'en' })
}
// Any other unknown value (including legacy ones we don't anticipate)
// falls through to detectInitialLocale().
```

Idempotent. No version flag needed.

## Architecture

### Locale detection

```ts
function detectInitialLocale(): Locale {
  const raw = (navigator.language || 'en').toLowerCase()
  if (raw.startsWith('zh-tw') || raw.startsWith('zh-hk') || raw.includes('hant')) return 'zh-TW'
  if (raw.startsWith('zh')) return 'zh-CN'
  const base = raw.split('-')[0]
  const known: Record<string, Locale> = {
    en: 'en', ja: 'ja', ko: 'ko', fr: 'fr', de: 'de', es: 'es', ru: 'ru',
  }
  return known[base] ?? 'en'
}
```

### First-paint resolution (D13)

`currentLocale` is initialized **synchronously** at module load so React's
first paint never sees `undefined` and never flashes English on a
non-English browser:

```ts
// reader/lib/i18n.ts
let currentLocale: Locale = detectInitialLocale()  // synchronous

// Fire-and-forget async reconciliation. Does NOT block first paint.
void (async () => {
  if (typeof chrome === 'undefined' || !chrome.storage?.local) return
  const stored = await chrome.storage.local.get('config_uiLanguage')
  const raw = stored.config_uiLanguage as string | undefined

  // One-time migration from the old 'en-US' code.
  if (raw === 'en-US') {
    await chrome.storage.local.set({ config_uiLanguage: 'en' })
    if (currentLocale !== 'en') { currentLocale = 'en'; notify() }
    return
  }
  // Returning user with an explicit choice — adopt it if different.
  if (raw && raw in MESSAGES && raw !== currentLocale) {
    currentLocale = raw as Locale
    notify()
  }
  // Otherwise: no stored value (new user) or unknown value — keep detection.
})()
```

Worst-case timeline:
- New user, `navigator.language=ja-JP`: first paint Japanese, no flash.
- Returning user who previously chose Korean on a Japanese browser: ~50ms
  Japanese → switches to Korean. One-shot, not a re-render storm.

### Reactivity (no Provider) + `<html lang>` sync (D9 / D18)

```ts
const subscribers = new Set<() => void>()
function notify() {
  // Keep <html lang> in sync so screen readers, :lang() CSS, and browser
  // spell-check use the right dictionary.
  if (typeof document !== 'undefined') {
    document.documentElement.lang = currentLocale
  }
  // D18: 一个订阅者抛错不可终止后续订阅者；分别 try/catch。
  subscribers.forEach((cb) => {
    try { cb() } catch (e) { console.warn('[i18n] subscriber failed', e) }
  })
}

export async function setLocale(l: Locale): Promise<void> {
  if (l === currentLocale) return
  currentLocale = l
  if (typeof chrome !== 'undefined' && chrome.storage?.local) {
    await chrome.storage.local.set({ config_uiLanguage: l })
  }
  notify()
}

// 跨标签同步（D9 修订版 — eng review 2026-04-25）
// 旧版只更新 currentLocale 不通知，导致跨 tab 切换不反应式生效。
if (typeof chrome !== 'undefined' && chrome.storage?.onChanged?.addListener) {
  chrome.storage.onChanged.addListener((changes, area) => {
    if (area !== 'local' || !changes.config_uiLanguage) return
    const v = changes.config_uiLanguage.newValue
    if (typeof v === 'string' && v in messages && v !== currentLocale) {
      currentLocale = v as Locale
      notify()
    }
  })
}

// 模块加载末尾立即调用一次 notify()（D9 / 1D — eng review 2026-04-25）
// 让 document.documentElement.lang 在首次 React render 之前已等于
// detectInitialLocale() 的同步结果。subscribers Set 此时为空，cb forEach
// 是 no-op；只有 <html lang> 副作用生效。
notify()

export function useT(): typeof t {
  useSyncExternalStore(
    (cb) => { subscribers.add(cb); return () => subscribers.delete(cb) },
    () => currentLocale,
  )
  return t
}
```

**注意**：`useT()` 强制重渲染但 `t` 函数 identity 不变。**不要**把 `t` 放到 `useEffect` 的 deps——locale 变化时 effect 不会重跑（这是设计意图，避免 useMemo deps 误触发，但容易踩到）。

Components migrate from `import { t }` to `import { useT }` + `const t = useT()` — one new line, all `t('xxx')` callsites unchanged.

Non-React callers (toast helpers, error handling) keep importing the
global `t()`. They evaluate at call time, so they always read the latest
`currentLocale`.

### Mid-stream switch behavior (D15)

In-flight AI streams are NOT cancelled or re-requested on `setLocale()`.
The stream's existing system prompt locked its output language at request
build time. The next AI request uses the new locale automatically (since
`langCfg()` reads `getLocale()` fresh on each build). No banner, no toast.

### Output "Auto" coupling + `'detect'` 选项 (D17)

```ts
// reader/lib/ai.ts
//
// 'detect' 路径保留旧 model-heuristic 行为；显式选 'detect' 的用户得到
// "model 自己判断"的 instruction，translateTarget 仍取当前 UI locale。
// 'auto' 路径走 D5 的 UI 耦合。
function langCfg(code: string | undefined): OutputLanguage {
  if (code === 'detect') {
    return OUTPUT_LANGUAGES.find((l) => l.code === 'detect')!
  }
  if (!code || code === 'auto') {
    const ui = getLocale()
    return OUTPUT_LANGUAGES.find((l) => l.code === ui)
        ?? OUTPUT_LANGUAGES.find((l) => l.code === 'en')!
  }
  return OUTPUT_LANGUAGES.find((l) => l.code === code)
      ?? OUTPUT_LANGUAGES.find((l) => l.code === 'en')!
}
```

`OUTPUT_LANGUAGES` 数组按 D17 新加 `'detect'` 项：

```ts
{ code: 'detect', label: 'Detect from question',
  instruction: "Respond in the reader's language if they asked in one; otherwise default to English.",
  translateTarget: '中文 (Simplified Chinese)' },
```

`langInstruction()`, `buildMessages()`, `buildChatMessages()`, and the
translate-selection path all flow through `langCfg()`, so all four AI
surfaces inherit the new behavior automatically.

`translateTarget` for Auto = the current UI locale's `translateTarget`
(e.g. UI=ja → translate-selection target = `日本語 (Japanese)`).
`'detect'` 的 translateTarget 仍是中文（保留旧默认）；如果 detect 用户想改翻译目标，他们自己显式选语言。

### Chat 历史语言锁定 (D16)

`chatBasePrompt`（`reader/lib/ai.ts:151`）现在追加一行，让模型从这一轮起严格使用目标语言、不被历史中的旧语言回答锚定：

```ts
function chatBasePrompt(lang: string | undefined): string {
  const cfg = langCfg(lang)
  return "You are a research assistant grounded in the paper below. Answer strictly from the paragraphs; cite them inline using `[pN]` where N is the paragraph index shown in the context. If the paper doesn't cover the question, say so directly.\n" +
    cfg.instruction + "\n" +
    `Past assistant turns may be in a different language; from this turn forward, respond strictly in ${cfg.translateTarget}.`
}
```

仅 chat 受影响——`buildMessages` / `buildSummaryMessages` / `buildVariantSummaryMessages` 没有历史拼接，无需此提示。

## UI Surface

### Options page changes (`options/main.tsx`)

#### UI language picker — 原生 `<select>` (D6, D14)

eng review 2026-04-25 修订：用原生 `<select>`，删除原方案的 `language-picker.tsx` 自定义组件。Options 页面**删除本地 `uiLanguage` state**，由 `useT()` 订阅 + `<select value={getLocale()}>` 直接读模块全局：

```tsx
// options/main.tsx — 实施草图
import { getLocale, setLocale, useT, type UiLocale } from '../reader/lib/i18n'
import { OUTPUT_LANGUAGES, detectInitialLocale } from '../reader/lib/ai'

function OptionsApp() {
  const t = useT()  // 订阅 currentLocale 变化（D13 异步 reconcile 触发的 notify 也会让组件重渲染）
  // ...其他 state
  const currentUi = getLocale()
  const detected = detectInitialLocale()
  const uiOrder = uiLocaleOrder(detected, currentUi)  // D14 排序

  return (
    <Field id="language" label={t('options.ui_language.label')} hint={t('options.ui_language.hint')}>
      <select
        value={currentUi}
        onChange={(e) => { void setLocale(e.target.value as UiLocale) }}
        style={{ ...input(), minWidth: 220, fontFamily: 'var(--font-i18n-fallback)' }}
      >
        {uiOrder.map((code) => (
          <option key={code} value={code} style={{ fontFamily: 'var(--font-i18n-fallback)' }}>
            {OUTPUT_LANGUAGES.find((l) => l.code === code)?.label}
          </option>
        ))}
      </select>
    </Field>
  )
}
```

##### UI language picker — order (D14)

```ts
function uiLocaleOrder(detected: UiLocale, current: UiLocale): UiLocale[] {
  const all = (OUTPUT_LANGUAGES
    .filter((l) => l.code !== 'auto' && l.code !== 'detect')
    .map((l) => l.code)) as UiLocale[]
  const order: UiLocale[] = []
  if (detected !== current) order.push(detected)        // D14: detected first
  order.push(current)                                   // D14: then current
  for (const code of all) {                             // D14: rest in declaration order
    if (!order.includes(code)) order.push(code)
  }
  return order
}
```

Native names (`日本語`, `한국어`, `Deutsch`, ...) display unchanged regardless of which UI locale is currently active — readers find their own language by sight.

### AccountMenu globe icon (D10) — discoverability hook

## Translation Quality Rules

Implementation-time guidelines for Claude (the translator):

1. **Brand / product nouns stay in English** — PaperFlow, BYOK, Pro, Sync,
   Free, Library, Memory, OTP, API key, OpenAI, Stripe, Google, arXiv, PDF.
2. **ICU placeholders preserved unchanged** — `{n}`, `{used}`, `{ui}`,
   `{date}`, `{tier}`, `{papers}`, `{highlights}`.
3. **Tone matches existing zh-CN voice** — direct, mildly informal, no
   over-formality.
4. **CJK politeness levels** — Japanese ですます; Korean 합니다 form.
5. **European formality** — French/German/Spanish/Russian use neutral
   written register.
6. **Length awareness** — German typically expands ~30%; for buttons
   ("Save", "Resend"), pick shorter equivalents (`OK` / `Senden`) to
   prevent layout breakage.
7. **Punctuation** — keep the existing `·` separator pattern; do not
   force locale-specific replacements.

### Font fallback stack

Mixed-script labels render with the following CSS variable, added to
`tokens.css`:

```css
:root {
  --font-i18n-fallback:
    system-ui,
    "PingFang SC",        /* macOS Simplified Chinese  */
    "PingFang TC",        /* macOS Traditional Chinese */
    "Hiragino Kaku Gothic ProN", /* macOS Japanese     */
    "Apple SD Gothic Neo",       /* macOS Korean       */
    "Microsoft YaHei",    /* Windows Chinese           */
    "Yu Gothic",          /* Windows Japanese          */
    "Malgun Gothic",      /* Windows Korean            */
    "Noto Sans CJK SC",   /* Linux fallback            */
    sans-serif;
}
```

The `LanguagePicker` component sets `font-family: var(--font-i18n-fallback)`
on its trigger button and listbox so all 9 native names render with a
consistent fallback chain across macOS / Windows / Linux. Other UI
elements continue using `--font-serif` / `--font-sans` from existing
tokens; only the picker is opted in (it's the only place where 9 scripts
appear together).

## Behavior Change Notice

**Old `'auto'` semantics:** model-heuristic — *"Respond in the reader's
language if they asked in one; otherwise default to English."*

**New `'auto'` semantics:** deterministic — `'auto'` resolves to the
current UI locale at AI request build time.

**Affected users:** anyone who has `outputLanguage = 'auto'` (the
default) AND whose typed-question language doesn't match their UI
locale. They will see AI responses switch from "matching the typed
question" to "matching the UI."

**Mitigation:** D17（eng review 2026-04-25）保留了 `'detect'` 选项，用户可以显式选择以恢复旧的 model-heuristic 行为。`'auto'` 仍是默认且解析为 UI locale；`'detect'` 是给"我用英文问、想要英文答"的旧用户的逃生通道。

**Users explicitly choosing a non-auto language are unaffected.**

  sees Japanese UI on first open, no manual configuration.
- **First-paint locale (D13)** — on fresh install with `navigator.language='ja-JP'`,
  the very first frame renders in Japanese. No English flash before Japanese
  appears. Verified by mocking `chrome.storage.local.get` to never resolve
